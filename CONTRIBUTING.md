# Contributing to ISO 10383

## The four rules

### 1. No heredocs for patch scripts

Write `/tmp/script.py`, run it standalone, check its exit code. Never inline Python with quotes or braces in a heredoc. Heredocs have silently corrupted files four times.

### 2. `set -euo pipefail` at the top of every shell script

A failed anchor must halt the script. Without this, patch scripts abort and the shell continues — nine times in v1.3.0 alone.

### 3. Adversarial tests on `/tmp` copies, never on the working tree

Copy the file, mutate the copy, verify the mutation. The working tree is not a test fixture.

### 4. File-first

Write a script to a file, run the file, read the output. Never execute critical logic inline.

## Source discipline

**Accepted source:** SWIFT's published MIC file. No third-party lists, mirrors, Wikipedia, aggregators. If a value can't be traced to the published file, the field stays null.

**Snapshots:** Every cross-referenced value validates against a committed snapshot. Regenerated by a script, committed, CI-verified.

**Hand-edits rejected.** Every change goes through a tool that sets `last_verified`, records the source URL, writes deterministically.

## Deterministic writes

```python
json.dumps(data, indent=2, sort_keys=True, ensure_ascii=False)
```

LF line endings. Trailing newline. Two runs on the same input produce byte-identical output.
## Export drift checks

Every exporter has a `--check` mode. Run before pushing:

    python3 tools/export_csv.py --check
    python3 tools/export_sql.py --check
    python3 tools/export_parquet.py --check
    python3 tools/sync_wrappers.py --check

If any reports `stale:`, regenerate the artifact:

    python3 tools/export_csv.py
    python3 tools/export_sql.py
    python3 tools/export_parquet.py
    python3 tools/sync_wrappers.py

The nine committed files at repo root are the contract with downstream
consumers. They are always derived from `iso10383.json`; never edit them
by hand.
