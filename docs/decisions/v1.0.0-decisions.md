# ISO 10383 v1.0.0 — Locked Decisions

Each decision is final until a new ADR supersedes it.

## D1 — New repository, not a monorepo

**Decision:** iso10383 is its own repository.
**Alternatives:** Extend Exchange Calendar; monorepo.
**Rationale:** An exchange is not a currency is not a country. Independent versioning and release cadence. Exchange Calendar has 74 exchange files with its own schema; coupling them forces coordination neither needs.

## D2 — One array, not three

**Decision:** Top-level `mics` array. `mic_type` ∈ {OPERATING, SEGMENT}. `status` ∈ {ACTIVE, UPDATED, EXPIRED}.
**Alternatives:** Separate `operating_mics`, `segment_mics`, `expired_mics`.
**Rationale:** Expired is a status, not a type. Splitting by status forces a move on every expiry and breaks `WHERE operating_mic = 'XNAS'` queries. One array with two orthogonal fields.
**Verified:** Release 2.0 factsheet confirms statuses are `active`, `updated`, `expired`.

## D3 — Self-reference is the pattern

**Decision:** `operating_mic` is non-null for every entry. Operating MICs point to themselves; segment MICs point to their parent.
**Alternatives:** `operating_mic` is null for operating MICs.
**Rationale:** The FAQ shows `ABCD` with `OPERATING MIC = ABCD` and `OPRT/SGMT = OPRT`. Self-reference is the published format, not a copy-paste artifact.
**Consequence:** Validator requires `operating_mic == mic` for OPERATING and forbids it for SEGMENT. No cycle-detection rule — it would break the file on row one.

## D4 — market_category uses the ISO codes exactly

**Decision:** Closed enum of the 16 codes: ATSS, APPA, ARMS, CTPS, CASP, DCMS, IDQS, MLTF, NSPD, OTFS, OTHR, RMOS, RMKT, SEFS, SINT, TRFS.
**Alternatives:** Expand to human-readable strings (EXCHANGE, MTF, SI).
**Rationale:** Consumers join on the code. "Regulated Market" is RMKT, not EXCH. "Systematic Internaliser" is SINT, not SI. Expansion breaks every join.

## D5 — Closed enums, unknown value raises

**Decision:** `mic_type`, `status`, `market_category` are closed enums. Unknown value raises at parse time.
**Alternatives:** Pass through; log and continue.
**Rationale:** A new value is a spec change. Silent coercion hides real amendments.

## D6 — Cross-registry validation via committed snapshots

**Decision:** `tools/iso3166_snapshot.json` holds alpha-2 codes. `tools/exchange_calendar_snapshot.json` holds MICs already in use. No runtime dependency.
**Alternatives:** Runtime fetch; shared monorepo.
**Rationale:** Same pattern as ISO 3166. Advisory in v1.0.0, blocking in v1.0.1. The bidirectional Exchange Calendar check is new and establishes the pattern for every pair after.

## D7 — Tooling: copy and adapt, no shared library

**Decision:** Port ISO 4217's validators and exporters. Adapt to the MIC schema.
**Alternatives:** Extract a shared toolkit first.
**Rationale:** Premature abstraction costs more than duplication. Extract only when a third registry is added.

## D8 — Versioning: single source, all references agree

**Decision:** `VERSION` is the single source of truth. `CHANGELOG.md` top heading, README badge, `meta.version`, Parquet footer must all match. CI fails on disagreement.
**Rationale:** The failure mode that cost ISO 4217 the most rework.

## D9 — Monthly refresh cadence, gated

**Decision:** SWIFT publishes the second Monday. CI fails if `meta.source_snapshot` is more than 60 days old.
**Alternatives:** Per-entry `last_verified` like ISO 3166.
**Rationale:** MICs are more volatile. One global snapshot date, not per-entry dates. One full missed cycle before failing. Distinct CI job, not a paragraph.

## D10 — REMOVED > 0 is a hard failure

**Decision:** A refresh diff with REMOVED > 0 fails the refresh PR until a human confirms.
**Rationale:** Removals are the change class most likely to break downstream consumers. Never silently remove.

## D11 — Out of scope for v1.0.0

**Decision:** Operating hours, MIC→LEI, MIC→BIC, MIC→ISIN, trading currency per MIC, regulatory status.
**Rationale:** Each is a separate companion file with its own source and cadence. Bundling dilutes the primary contract.

## D12 — release.sh ported before v1.0.0

**Decision:** `scripts/release.sh` adapted from ISO 3166 in Phase 0 or Phase 1.
**Rationale:** The script makes every subsequent release cheap. Finding its bugs on v1.0.0 is cheaper than on v1.1.0.

## D13 — CONTRIBUTING.md written before the code

**Decision:** `CONTRIBUTING.md` at Phase 0 with the four rules.
**Rationale:** The four rules cost one hour to write and save weeks.

## D14 — Don't write v1.1.0's roadmap

**Decision:** No roadmap for v1.1.0+ until v1.0.0 has shipped.
**Rationale:** ISO 3166's v1.1.0, v1.2.0, v1.3.0 roadmaps were all wrong. Scope should be discovered from consumers, not planned.
